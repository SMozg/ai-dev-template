## Customer Journey Map (CJM)

Файл: `.claude/memory/cjm.md` — полный путь клиента с текстами и кнопками.

### Формат CJM — 5 уровней иерархии с табуляцией

```
# Секция (группа уровней)
	## Уровень
		### Блок (группа связанных шагов)
			#### Шаг (одно сообщение бота)
				содержание: текст, пометки TG/MAX
				##### Кнопки
					- [ кнопка ] → callback / действие
```

- Каждый уровень вложенности сдвинут **на 1 таб** от родителя
- Содержание шага сдвинуто **на 1 таб** от заголовка шага
- В VS Code все уровни сворачиваются по заголовкам
- Полные тексты сообщений — обязательны (чтобы "прожить" путь клиента в файле)
- Анимации и повторяющиеся паттерны — ссылка на первое вхождение

### При изменении CJM
- Обновить `.claude/memory/cjm.md`
- Проверить синхронность всех платформ (текст, кнопки, callbacks)

## Правила кода (нарушение = баг)

1. **Бизнес-логика ТОЛЬКО в core/.** Хендлеры — тонкие обёртки.
2. **Тексты ТОЛЬКО в core/texts.py.** Никаких хардкод-строк в хендлерах.
3. **Любая фича реализуется в core/ и оборачивается для каждой платформы.**
4. **Core не знает о платформах.** Никаких платформенных импортов в core/.
5. **Конфигурация через переменные окружения**, не хардкод.

## Процесс разработки

### Перед началом любой фичи
1. Заполнить `docs/BRIEF_TEMPLATE.md` -> сохранить как `docs/briefs/YYYY-MM-DD_название.md`
2. Показать пользователю бриф
3. Дождаться "ок"
4. Создать/обновить `docs/TODO.md` с шагами
5. Только потом писать код

### Во время работы
- Отмечать каждый шаг в `docs/TODO.md` сразу после выполнения

### Деплой
1. **Два прохода по CJM в коде** (обязательно до деплоя):
   - 🧪 Тестировщик: трассировка хендлеров + callback-кнопок (контекст совпадает?) + post-action flow на каждом уровне + grep на мусор + sync платформ
   - 📋 Продакт: тексты/кнопки в порядке CJM + всегда есть кнопка следующего действия (нет тупиков) + все ветки проверены
2. Скопировать файлы на прод
3. Перезапустить сервисы
4. Попросить пользователя проверить
5. **ТОЛЬКО после "ок"** — считать задачу завершённой

### После завершения — Документатор:
- `git add` + `git commit` + `git push`
- Обновить `docs/TODO.md` (отметить выполненное)
- Обновить файл памяти, если менялись архитектура / CJM / инциденты
